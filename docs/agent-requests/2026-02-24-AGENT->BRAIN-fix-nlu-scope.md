# Request from AGENT to BRAIN: Fix target_scope Parsing and Fallback Generation

## Context
A user reported that when they run a command like "첫 줄의 글자 크기를 30pt로 만들어" (Make the first line's font size 30pt), the entire document's font size is still changed instead of just the first line. 

While the `windows-agent` side has explicitly patched `_hwpx_apply_style` to isolate paragraph styling on `first_line`, the Python code generated by `windows-brain` continues to send `scope='all'`.

## Root Cause Analysis
Upon reviewing the `windows-brain` logic, we found two issues:
1. **NLU Parsing Flaw (`app/nlu.py`)**: The `NLUEngine.parse` method checks for `if "첫줄" in normalized`. Because the user sentence contains a space ("첫 줄"), it fails to match and defaults to `target_scope="all"`.
2. **Orchestrator Fallback Bug (`app/orchestrator.py`)**: When LLM generation fails or defaults to rule-based fallback generation, `orchestrator._build_run_body` correctly extracts `directive.get("scope", "all")`, but when building the line for `set_font_size` (and other style endpoints), it does not properly inject the detected `scope` parameter in some rule chains or ignores it. Make sure that when falling back to the `rule-based` model, the generated python script includes `scope='first_line'`.

## Requested Action
Please update the following in `windows-brain`:
1. In `app/nlu.py`: Update the parsing condition to `if "첫줄" in normalized or "첫 줄" in normalized or "first line" in normalized:`.
2. In `app/orchestrator.py`: Ensure that when building the fallback python script inside `_build_run_body`, the `scope` variable extracted from the Plan's directives is correctly used inside the `set_font_size`, `set_bold`, etc., `lines.append(f"controller.set_font_size({{size_i}}, scope='{{scope}}')")` statements.
3. Add or update Pytest tests to verify that `target_scope` is correctly inferred from "첫 줄의".
